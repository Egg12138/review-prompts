# 无线 mac80211 子系统

## mac80211 MLO 回调结构

在 mac80211 回调之间错误地放置 `BSS_CHANGED_*` 事件处理会导致运行时 `WARN_ON_ONCE` 触发、功能退化（关联失败、信标处理错误）或难以诊断的静默硬件异常行为。

mac80211 多链路操作（MLO）支持将传统的 `bss_info_changed()` 回调拆分为 `struct ieee80211_ops`（定义在 `include/net/mac80211.h`）中的两个回调：

- **`vif_cfg_changed()`**：处理来自 `struct ieee80211_vif_cfg` 的 VIF 全局配置变更，适用于整个虚拟接口
- **`link_info_changed()`**：处理来自 `struct ieee80211_bss_conf` 的每链路配置变更，适用于单个链路

如果既没有实现 `vif_cfg_changed()` 也没有实现 `link_info_changed()`，mac80211 会回退到为所有事件调用 `bss_info_changed()`。

权威的拆分定义在 `net/mac80211/main.c` 的 `BSS_CHANGED_VIF_CFG_FLAGS` 中。列在该宏中的标志是 VIF 全局的；其他所有都是链路特定的。将 VIF 全局标志传递给 `ieee80211_link_info_change_notify()` 会触发 `WARN_ON_ONCE`，将链路特定标志传递给 `ieee80211_vif_cfg_change_notify()` 也会触发 `WARN_ON_ONCE`。

### VIF 全局事件（属于 vif_cfg_changed()）

| 事件 | 数据位置 |
|------|---------|
| `BSS_CHANGED_ASSOC` | `vif->cfg.assoc` |
| `BSS_CHANGED_IDLE` | `vif->cfg.idle` |
| `BSS_CHANGED_PS` | `vif->cfg.ps` |
| `BSS_CHANGED_IBSS` | `vif->cfg.ibss_joined` |
| `BSS_CHANGED_ARP_FILTER` | `vif->cfg.arp_addr_list` |
| `BSS_CHANGED_SSID` | `vif->cfg.ssid` |
| `BSS_CHANGED_MLD_VALID_LINKS` | `vif->valid_links` |
| `BSS_CHANGED_MLD_TTLM` | MLD TID-to-link 映射 |

"数据位置"列显示携带已变更值的 `struct ieee80211_vif` 字段。

### 链路特定事件（属于 link_info_changed()）

| 事件 | 说明 |
|------|------|
| `BSS_CHANGED_BSSID` | BSSID 是 `struct ieee80211_bss_conf` 中的每链路属性 |
| `BSS_CHANGED_BEACON_INFO` | 信标参数（例如 `dtim_period`）是每链路的 |
| `BSS_CHANGED_BEACON` | 信标数据是每链路的 |
| `BSS_CHANGED_BEACON_INT` | 信标间隔是每链路的 |
| `BSS_CHANGED_ERP_CTS_PROT` | ERP 保护是每链路的 |
| `BSS_CHANGED_ERP_PREAMBLE` | 前导码类型是每链路的 |
| `BSS_CHANGED_ERP_SLOT` | 时隙定时是每链路的 |
| `BSS_CHANGED_HT` | HT 参数是每链路的 |
| `BSS_CHANGED_BASIC_RATES` | 基本速率是每链路的 |
| `BSS_CHANGED_TXPOWER` | 发射功率是每链路的 |
| `BSS_CHANGED_BANDWIDTH` | 信道带宽是每链路的 |
| `BSS_CHANGED_HE_BSS_COLOR` | BSS 颜色是每链路的 |
| `BSS_CHANGED_TPE` | 发射功率包络是每链路的 |

## Invariants（不变式）

- `BSS_CHANGED_VIF_CFG_FLAGS` 中列出的标志是 VIF 全局的，应路由到 `vif_cfg_changed()`
- 所有其他 `BSS_CHANGED_*` 标志是链路特定的，应路由到 `link_info_changed()`
- 错误路由会导致运行时 `WARN_ON_ONCE`
- `BSS_CHANGED_PS` 从 `vif->cfg.ps` 读取，属于 `vif_cfg_changed()`，而不是 `link_info_changed()`

## Failure Modes（故障模式）

| 违规操作 | 结果 |
|---------|------|
| 将 VIF 全局标志传递给 `link_info_changed()` | `WARN_ON_ONCE` 触发 |
| 将链路特定标志传递给 `vif_cfg_changed()` | `WARN_ON_ONCE` 触发 |
| MLO 迁移时事件错误路由 | 关联失败、信标处理错误、静默硬件异常 |

## Quick Checks（快速检查清单）

- [ ] 每个 `BSS_CHANGED_*` 标志是否根据 `BSS_CHANGED_VIF_CFG_FLAGS` 分类到了正确的回调？
- [ ] 将传统 `bss_info_changed()` 驱动迁移到 MLO 时，是否做了正确的路由？
- [ ] `BSS_CHANGED_PS` 是否在 `vif_cfg_changed()` 中处理？（而不是 `link_info_changed()`）
- [ ] 路径选择或挂起/恢复路径中 `ieee80211_vif_cfg_change_notify()` 和 `ieee80211_link_info_change_notify()` 的传递匹配 BSS_CHANGED_* 标志类型？
