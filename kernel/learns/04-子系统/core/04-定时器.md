# 定时器（Timer）子系统核心知识

## 定时器类型对比

### timer_list（低精度定时器）

- 分辨率：jiffies（取决于 HZ，1-10ms）
- 回调上下文：**softirq**（timer softirq）
- 回调中不能睡眠

| 操作 | API |
|------|-----|
| 初始化 | `timer_setup(timer, callback, flags)` 或 `DEFINE_TIMER()` |
| 启动 | `mod_timer(timer, expires)` 或 `add_timer(timer)` |
| 取消 | `timer_delete()` / `timer_delete_sync()` |
| 拆除 | `timer_shutdown_sync()` — 取消并阻止重新启动 |
| 回调中重新启动 | 在回调内调用 `mod_timer()` |

### hrtimer（高精度定时器）

- 分辨率：纳秒（`ktime_t`）
- 回调上下文：默认 **hardirq**，`HRTIMER_MODE_SOFT` 时为 **softirq**
- 返回值：`HRTIMER_NORESTART`（停止）或 `HRTIMER_RESTART`（继续）

| 操作 | API |
|------|-----|
| 初始化 | `hrtimer_setup(timer, callback, clock_id, mode)` |
| 启动 | `hrtimer_start(timer, time, mode)` 或 `hrtimer_start_range_ns()` |
| 取消 | `hrtimer_cancel()`（同步）或 `hrtimer_try_to_cancel()`（回调执行中返回 -1）|
| 回调中重新调度 | `hrtimer_forward_now()` 然后返回 `HRTIMER_RESTART` |
| Pinned 模式 | `HRTIMER_MODE_*_PINNED`：定时器在启动它的 CPU 上触发 |

### delayed_work（基于 workqueue 的定时器）

- 回调上下文：**进程上下文**（可以睡眠）

| 操作 | API |
|------|-----|
| 初始化 | `INIT_DELAYED_WORK(dwork, callback)` |
| 启动 | `schedule_delayed_work(dwork, delay)` 或 `queue_delayed_work(wq, dwork, delay)` |
| 取消 | `cancel_delayed_work_sync()` — 等待回调完成 |

## 执行上下文约束

| 操作 | timer_list (softirq) | hrtimer (hardirq) | hrtimer SOFT (softirq) | delayed_work (process) |
|------|---------------------|-------------------|----------------------|----------------------|
| 睡眠/调度 | 禁止 | 禁止 | 禁止 | 允许 |
| mutex_lock | 禁止 | 禁止 | 禁止 | 允许 |
| GFP_KERNEL 分配 | 禁止 | 禁止 | 禁止 | 允许 |
| spin_lock | 允许 | 允许 | 允许 | 允许 |
| spin_lock_bh | 冗余（用 spin_lock） | 禁止 (WARN_ON) | 冗余（用 spin_lock） | 允许 |
| spin_lock_irqsave | 允许 | 允许 | 允许 | 允许 |
| RCU 读侧 | 允许（隐式） | 允许（隐式） | 允许（隐式） | 需要 rcu_read_lock() |

## 定时器回调中不安全的操作（softirq/hardirq 上下文）

- 睡眠函数：`msleep()`, `ssleep()`, `usleep_range()`
- 阻塞等待：`wait_for_completion()`, `wait_event()`
- 睡眠锁：`mutex_lock()`, `down()`
- 非原子分配：`kmalloc(..., GFP_KERNEL)` — 使用 `GFP_ATOMIC`
- 用户内存访问：`copy_to_user()`, `copy_from_user()`
- `vfree()` — 实际安全（`in_interrupt()` 时通过 `vfree_atomic()` 自动延迟），可显式调用 `vfree_atomic()`
- `synchronize_rcu()` — 改用 `call_rcu()`
- `flush_work()`, `flush_workqueue()` — 可能睡眠

## 同步取消语义

### Invariants

- `timer_delete_sync()` 自旋等待回调完成
- **从定时器自己的回调中调用同步取消会导致死锁**
- 如果调用者持有回调也获取的锁，同步取消会导致死锁
- 非同步 `timer_delete()` 仅出队；回调可能仍在运行
- `timer_shutdown_sync()` 永久阻止重新启动（仅用于拆除路径）

### Failure Modes

```c
// 正确：释放前同步取消
timer_shutdown_sync(&obj->timer);
kfree(obj);

// 错误：非同步取消后释放 —— 回调可能仍在运行！
timer_delete(&obj->timer);
kfree(obj);                 /* use-after-free */

// 错误：持有回调的锁时同步取消 —— 死锁！
spin_lock(&obj->lock);
timer_delete_sync(&obj->timer);  /* 如果回调获取 obj->lock 则死锁 */
spin_unlock(&obj->lock);
```

---

## timer_pending() 不是同步

- 返回定时器是否已入队，但检查后可能立即变化
- 定时器不 pending 时，回调可能仍在另一个 CPU 上执行
- **不能用作证明回调未运行的依据**

---

## API 名称变化（已移除的旧 API）

- `del_timer()`, `del_timer_sync()` 已移除；改用 `timer_delete()`, `timer_delete_sync()`
- `hrtimer_init()` 已移除；改用 `hrtimer_setup(timer, callback, clock_id, mode)`
- `setup_timer()` 和 `init_timer()` 已移除
- `timer_shutdown_sync()` 用于拆除路径

---

## Quick Checks

- 定时器未同步取消就被释放 -> use-after-free
- 从自身回调调用同步取消 -> 死锁
- 持有回调也获取的锁时调用同步取消 -> 死锁
- `timer_pending()` 用于同步 -> 竞态条件
- 从 timer/hrtimer 回调中调用可睡眠函数 -> crash
- `timer_delete()`（非同步）后释放 -> use-after-free
- hrtimer 回调不返回 `HRTIMER_RESTART` 或 `HRTIMER_NORESTART` -> 未定义行为
- `timer_shutdown_sync()` 后调用 `mod_timer()` -> 静默无操作
