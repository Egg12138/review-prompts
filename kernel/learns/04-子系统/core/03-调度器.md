# 调度器（Scheduler）子系统核心知识

## Runqueue 锁定

Runqueue 锁是 `raw_spinlock_t`（即使在 PREEMPT_RT 上也不睡眠）。

### Invariants

- 多 runqueue 操作必须以一致顺序锁定以防止死锁。`double_rq_lock()` / `double_rq_unlock()` 自动处理顺序（内部通过 `rq_order_less()` 交换为升序）
- `lockdep_assert_rq_held()` 验证访问器中 rq 锁已持有
- `task_rq(p)` 扩展为 `cpu_rq(task_cpu(p))`。如果不固定或持有 `pi_lock` / rq 锁，任务可能在读取 `task_cpu(p)` 后迁移，导致调用者获得 CPU A 的 runqueue 而任务现在在 CPU B 上

### Failure Modes

**绝不要在任务处于不一致状态时释放 rq 锁** —— `p->on_rq`、RB-tree 和 `p->__state` 必须在锁释放前一致。其他 CPU 在解锁后立即观察到这些字段：

- 任务在树中但 `on_rq == 0`：`try_to_wake_up()` 看到 `on_rq == 0` 并调用 `activate_task()` —— 双重入队损坏 RB-tree
- `on_rq == 1` 但不在树中：`try_to_wake_up()` 看到 `on_rq == 1` 并跳过入队，但 `pick_next_task` 永远找不到该任务 —— 任务永久丢失
- `TASK_RUNNING` 且 `on_rq == 0`：`try_to_wake_up()` 看到 `TASK_RUNNING` 并提前返回（无需唤醒）—— 任务永远挂起，无法恢复

## 任务状态转换

### Voluntray Sleep 模式

正确模式：**在检查条件之前设置状态**，否则检查和状态变更之间的唤醒会丢失。

```c
// 正确 —— 状态在条件检查前设置
set_current_state(TASK_UNINTERRUPTIBLE);
if (!condition)
    schedule();
set_current_state(TASK_RUNNING);

// 错误 —— 如果条件在检查和 set_current_state 之间变更，唤醒丢失
if (!condition) {
    set_current_state(TASK_UNINTERRUPTIBLE);  // 唤醒已发生
    schedule();                                // 永远睡眠
}
```

### Invariants

- `set_current_state()` 使用 `smp_store_mb()`，因此状态写相对于之后的内存访问（条件检查）是有序的
- `TASK_DEAD` 需要特殊处理 —— 任务不能被重新调度
- `wake_up_process()` 调用 `try_to_wake_up()` 带 `TASK_NORMAL`（`TASK_INTERRUPTIBLE | TASK_UNINTERRUPTIBLE`）；无论目标任务的状态如何调用都是安全的（如果不在可唤醒状态则返回 0）

### Failure Modes

丢失唤醒使任务永远睡眠且无法恢复。遗漏状态 barrier 使唤醒在条件检查之前通过。

## CPU 亲和性与迁移

### 关键 API

- `set_cpus_allowed_ptr()`：更改任务允许的 CPU 掩码
- `kthread_bind()`：将 kthread 限制到特定 CPU（必须在 kthread 启动前调用）
- `stop_one_cpu()`：可能需要用于强制迁移
- `migrate_disable()`：阻止迁移但**不禁用抢占或阻止睡眠**；任务可以在迁移禁用时阻塞

### Invariants

- 迁移必须相对于允许的 CPU `cpumask_subset()`
- 迁移前检查 `is_migration_disabled()`
- CPU 热插拔需要特别注意 —— 任务不能被迁移到正在下线的 CPU

### Failure Modes

将任务迁移到不允许的 CPU 或无锁迁移会导致 crash、违反 cpuset 约束或损坏 per-CPU 数据。

## CFS（SCHED_NORMAL / SCHED_BATCH / SCHED_IDLE）

### EEVDF 算法

选择 eligible（`lag >= 0`，即被欠服务）且虚拟截止时间最早的任务。

- 虚拟截止时间：`vd = vruntime + vslice`，其中 `vslice = calc_delta_fair(slice, se)` 计算 `slice * NICE_0_LOAD / weight`
- 基础 slice：`sysctl_sched_base_slice`（默认 700 微秒）；入队时由 `place_entity()` 重新计算截止时间

### 关键字段

| 字段 | 含义 |
|------|------|
| `se->vruntime` | per-entity 加权 CPU 时间的单调计数器；CPU 之间迁移时必须归一化 |
| `se->min_vruntime` | 增强 RB-tree 字段，跟踪子树中最小的 `vruntime`；用于 `__pick_eevdf()` 中的 O(log n) 资格剪枝 |
| `se->vlag` | 跟踪服务赤字/盈余；`vlag = V - vruntime`，V 是加权平均 vruntime；在 enqueue/dequeue 时由 `place_entity()` 保持；当 `se->on_rq` 且 `cfs_rq->curr == se` 时，同一联合字段用作 `vprot` |
| `se->on_rq` | 入队时设为 1；通过延迟出队（`sched_delayed`），实体在逻辑出队后可保持 `on_rq == 1` 直到资格耗尽 |
| Load weight | 从 nice 值通过 `sched_prio_to_weight[]` 派生；每个 nice 级别 ~10% 变化 |

### RB-Tree 结构

RB-tree 按 `se->deadline` 排序，每个节点增强 `se->min_vruntime`，使 `__pick_eevdf()` 能够进行 O(log n) 资格剪枝。如果子树的 `min_vruntime` 显示没有合格实体（通过 `vruntime_eligible()` 检查），整个子树可被跳过。

### PELT（Per-Entity Load Tracking）

- `update_load_avg()` 必须在任何实体状态变更（enqueue/dequeue/migration）**之前**调用，以保持层级一致性
- 跟踪每个实体和每个 `cfs_rq` 的利用率的衰减平均
- 迁移时：`DO_ATTACH` 将负载附加到新 CPU，`DO_DETACH` 从旧 CPU 分离

### Failure Modes

过时或不正确的负载平均值导致错误的负载均衡决策、错误的频率选择和容量估算错误。

### CFS 带宽

- 组限制使用 `cfs_rq->runtime_remaining`
- 必须在限制时正确出队，在解除限制时正确入队
- 层级性：父级限制影响所有子级

### Failure Modes

不正确的限制/解除限制顺序导致任务被永久限制或超过带宽配额。

## 实时（SCHED_FIFO / SCHED_RR）

### 优先级

优先级范围 1-99（用户空间）；数字越大优先级越高。内核内部优先级是反转的（`MAX_RT_PRIO - 1 - rt_priority`）。

### RT 带宽

`/proc/sys/kernel/sched_rt_runtime_us` / `sched_rt_period_us` 防止 CPU 垄断（默认 95% 限制 —— 每 1000ms 周期内 950ms）。

### Failure Modes

错误的优先级映射或缺失带宽限制可使所有非 RT 任务饿死并挂起系统。

---

## Deadline（SCHED_DEADLINE）

### Invariants

- **`runtime <= deadline <= period`** — 违反此不变性导致截止时间错过或 CPU 过载，破坏所有 DL 任务的实时保证
- 准入控制：总带宽 `sum(runtime_i / period_i)` 不能超过 `M * (rt_runtime / rt_period)`，M 是根域中活跃 CPU 的数量（由 `dl_bw_cpus()` 计算）
- CBS（Constant Bandwidth Server）强制带宽隔离
- GEDF（Global Earliest Deadline First）：在 M-CPU 系统上，应运行最早截止时间的 M 个任务
- DL 任务按根域跟踪以进行迁移决策

### Failure Modes

- 运行时耗尽时任务被限制，下一个周期（补充）时解除限制

## sched_ext（SCHED_EXT — BPF 可扩展调度器）

调度行为通过 BPF 程序的 ops 回调定义（`select_cpu`, `enqueue`, `dispatch` 等）。

### 关键概念

- **Dispatch Queues (DSQ)**：任务排入本地（per-CPU）、全局或自定义 DSQ；可以使用 FIFO 或 PRIQ (vtime) 顺序但不能混合
- **`ops_state` 追踪**：原子操作 `p->scx.ops_state` 防止对同一任务的并发 BPF 操作；转换：NONE -> QUEUEING -> QUEUED -> DISPATCHING
- **Direct dispatch**：允许入队路径通过 per-CPU `direct_dispatch_task` 标记直接调度到本地 DSQ 的优化
- **Failsafe**：watchdog timeout, `scx_error()`, 和 SysRq-S 都触发自动回退到 CFS

### Failure Modes

BPF 调度器 ops 中的 bug 可能使任务停滞、损坏调度队列或触发 watchdog failsafe 导致回退到 CFS。

---

## 优先级继承

高优先级任务在阻塞在低优先级任务持有的锁上时，锁持有者暂时继承被阻塞任务的优先级。

### Invariants

- PI 链必须原子更新；检查环路以检测死锁
- RT mutex 是主要用例
- `pi_lock` 保护 PI 状态；遍历链时必须持有

### Failure Modes

损坏的 PI 链导致无限优先级反转，使高优先级任务无限期阻塞在低优先级锁持有者后面。

---

## CPU 热插拔生命周期

### 回调节点

- `sched_cpu_deactivate()`：将 CPU 从活动调度中移除（清除 `cpu_active_mask`，设置 `balance_push`，拆除调度域）
- `sched_cpu_dying()`：在 CPU 仍在线但正在 dying 时调用；停止需要 CPU 仍在有效状态的定时器（如 `dl_server_stop()` 取消 dl_server hrtimer）

### Invariants

- 在离线 CPU 上触发的 per-CPU 调度器资源（hrtimers, callbacks, servers）触发警告或访问无效的 per-CPU 数据结构
- 修改限制 per-CPU 定时器武装的机制（移除检查、更改条件）时，验证定时器不能在 CPU 离线窗口期间被武装 —— 限制机制可能一直提供隐式的热插拔协调
- `dl_server` 使用 hrtimer（`struct sched_dl_entity` 中的 `dl_timer`），如果定时器在 CPU 从 `cpu_present_mask` 移除后触发，`cpudl_set()` 会触发 `WARN_ON`
- `dl_server_start()` 检查 `cpu_online()` 并在 CPU 离线时提前返回

### Failure Modes

在离线 CPU 上触发的定时器访问无效的 per-CPU 数据结构，导致警告或 crash。

---

## Quick Checks

- `preempt_disable()` / `preempt_enable()` 必须始终保持平衡
- `set_task_cpu()` 仅在迁移时安全，需持有正确锁
- 绝不在禁用抢占或持有非 rq 锁时调用 `schedule()`
- 绝不对已在 runqueue 上的任务执行 enqueue
