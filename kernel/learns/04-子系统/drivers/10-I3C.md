# I3C 总线子系统

## 概述

I3C（Improved Inter Integrated Circuit）是 MIPI 联盟定义的下一代串行通信总线，旨在取代传统的 I2C 总线。它提供更高的速度（最高 12.5MHz）、更低的功耗、带内中断（IBI，In-Band Interrupt）和动态地址分配。Linux I3C 子系统位于 `drivers/i3c/`，提供核心框架、总线控制器驱动和从设备驱动。

---

## I3C 总线架构

### 总线上设备类型

| 类型 | 说明 |
|------|------|
| **I3C Master（主控）** | 管理总线的控制器。每个 I3C 总线有一个主控 |
| **I3C Target（从设备）** | 原生 I3C 设备，支持 I3C 协议特性 |
| **I2C Legacy Device（传统 I2C 设备）** | 兼容 I2C 的设备，挂载在 I3C 总线上但只能使用 I2C 协议 |

### 核心数据结构

| 结构体 | 用途 |
|--------|------|
| `struct i3c_master_controller` | 表示 I3C 主控制器 |
| `struct i3c_dev_desc` | 描述 I3C 从设备 |
| `struct i2c_dev_desc` | 描述传统 I2C 设备 |
| `struct i3c_device` | I3C 从设备的驱动级表示 |
| `struct i3c_driver` | I3C 设备驱动 |

## 设备发现与地址分配

### 动态地址分配（DAA）

I3C 总线的标志性特性之一：

- 每个 I3C 设备有一个唯一的 48-bit 动态地址（Dynamic Address，DA）和一个可选的静态地址（Static Address，SA）
- 总线启动时，主控执行 DAA（Dynamic Address Assignment，动态地址分配）流程，为所有设备分配地址
- 设备可以有一个初始动态地址（Initial Dynamic Address，IDA）或在 DAA 过程中获取新地址

### 设备宣告

I3C 设备通过以下机制向主控宣告自己：

- **ENTDAA（Enter Dynamic Address Assignment）**：进入 DAA 模式，所有设备参与地址分配
- **IBI（In-Band Interrupt）**：带内中断机制，设备可主动向主控发送事件通知
- **Hot-Join（热加入）**：新设备在总线已运行时加入并触发 DAA

### 不变式

- DAA 必须在任何 I3C 通信前成功完成
- IBI 的处理不得阻塞 DAA 或正常的 I3C 数据传输
- Hot-Join 事件的处理必须正确维护地址分配的完整性

## I3C 驱动编程模型

### 主控制器驱动

I3C 主控制器驱动必须实现 `struct i3c_master_controller_ops` 中的方法：

| 回调 | 说明 |
|------|------|
| `bus_init` | 初始化 I3C 总线（包括 DAA） |
| `send_ccc_cmd` | 发送 CCC（Common Command Code，通用命令码） |
| `priv_xfers` | 执行私有数据传输 |
| `i2c_xfers` | 执行 I2C 兼容传输 |
| `do_daa` | 执行动态地址分配 |
| `enable_ibi` | 启用指定设备的 IBI |
| `disable_ibi` | 禁用指定设备的 IBI |
| `recycle_ibi_slot` | 回收 IBI 槽位 |

### 从设备驱动

I3C 从设备驱动使用 `struct i3c_driver`，通过 `i3c_driver_register()` 注册，需匹配 Device Tree 中的兼容字符串或提供 `id_table`。

### 不变式

- 总线控制器驱动必须正确处理 DAA 期间的总线事件
- IBI 处理函数必须在原子上下文中考虑性能（禁止长时间休眠操作）
- 私有数据传输应合理处理超时和错误恢复

## IBI（带内中断）处理

### 核心机制

IBI 是 I3C 相比 I2C 的主要优势，允许从设备在无需主控轮询的情况下发起通信。

### 处理流程

1. 从设备通过总线请求 IBI（发出 SDR 或 HDR 开始条件后跟目标地址和相关模式）
2. 主控检测到 IBI 请求，停止当前事务并处理 IBI
3. 主控调用注册的 IBI 处理回调
4. IBI 处理完成后，主控恢复被中断的事务

### 不变式

- IBI 使能和禁用请求必须通过主控的 `enable_ibi` / `disable_ibi` 正确序列化
- IBI 槽位（slot）管理必须正确，避免槽位耗尽
- IBI 处理回调中不应执行可能导致休眠的长时间操作
- 必须注意 IBI 与正常数据传输之间的竞态条件

## Device Tree 绑定

### 关键属性

I3C 控制器在 Device Tree 中通过以下关键属性描述：

- `compatible`：I3C 主控兼容字符串
- `#address-cells` 和 `#size-cells`：地址描述
- `i3c-scl-hz`：SCL 时钟频率
- `i2c-scl-hz`：I2C 兼容模式下的 SCL 频率
- 子节点：连接的从设备，需指定 `reg`（地址）和 `assigned-address`（分配的动态地址）

### 不变式

- I3C 子节点的 `reg` 属性中最高位（BIT(31)）表示设备类型：1 为 I3C 设备，0 为 I2C 设备
- I2C 设备子节点应满足 `i2c.txt` 绑定文档的要求
- I3C 设备可以选择性地指定 `assigned-address` 来提供一个首选动态地址

## 故障模式

### 1. DAA 失败未正确处理

DAA 流程中部分设备可能响应失败（如设备被移除或损坏）。主控必须优雅地处理这些错误而不是中止整个枚举过程。

### 2. IBI 路由错误

IBI 发送到主控后，主控可能错误地路由到不正确的设备处理程序，导致事件丢失或数据损坏。驱动必须根据目标地址正确分发 IBI。

### 3. 地址冲突

动态地址分配可能出现地址冲突（两个设备声明相同的动态地址）。主控的 DAA 流程必须检测并解决这些冲突。

### 4. IBI 槽位耗尽

如果 IBI 处理慢于 IBI 到达速度，IBI 槽位将耗尽。驱动必须实现适当的流控制或缓冲区管理。

### 5. 动态设备移除时的资源清理

设备热移除时驱动必须确保：已排队的 IBI 已取消、数据传输已终止、分配的内存已释放。

---

## 快速检查清单

- **DAA 完整性**：确保所有 I3C 设备在通信前经过完整的 DAA 流程
- **IBI 处理上下文**：IBI 处理函数不应执行长时间操作或调用可休眠函数
- **地址管理**：关注动态地址分配中的冲突检测和解决机制
- **Device Tree 绑定**：正确设置 `reg` 最高位区分 I3C 和 I2C 设备
- **资源释放**：设备移除时清理 IBI 队列和数据传输状态
- **错误恢复**：传输超时或 DAA 失败时做到优雅恢复而不破坏总线状态
