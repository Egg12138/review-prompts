# MM 回收、交换与迁移

## 写回标签（Writeback Tags）

不正确的标签处理会导致数据丢失（脏页在同步期间被跳过）或写回活锁（同步永远无法完成，因为新的脏页不断出现）。审查任何启动写回或实现 `->writepages` 的代码。

页缓存标签定义为 `PAGECACHE_TAG_*` 在 `include/linux/fs.h`：

| 标签 | XA 标记 | 用途 |
|------|---------|------|
| `PAGECACHE_TAG_DIRTY` | `XA_MARK_0` | Folio 有脏数据需要写回 |
| `PAGECACHE_TAG_WRITEBACK` | `XA_MARK_1` | Folio 当前正在进行 IO |
| `PAGECACHE_TAG_TOWRITE` | `XA_MARK_2` | Folio 为当前写回趟次标记 |

**标签生命周期：**
1. `folio_mark_dirty()` 设置 `PAGECACHE_TAG_DIRTY`
2. `tag_pages_for_writeback()` 将 DIRTY 复制到 TOWRITE，用于数据完整性同步，防止新脏页造成的活锁
3. `folio_start_writeback()`（`__folio_start_writeback(folio, false)` 的宏）：
   - 设置 `PAGECACHE_TAG_WRITEBACK`
   - 如果 folio 的脏标志未设置，则清除 `PAGECACHE_TAG_DIRTY`
   - 清除 `PAGECACHE_TAG_TOWRITE`（因为 `keep_write` 为 false）
4. 要保留 `PAGECACHE_TAG_TOWRITE`，调用 `__folio_start_writeback(folio, true)`

**标签选择**（参见 `wbc_to_tag()` 在 `include/linux/writeback.h`）：
- `wbc_to_tag()` 对 `WB_SYNC_ALL` 或 `tagged_writepages` 模式返回 `PAGECACHE_TAG_TOWRITE`，否则返回 `PAGECACHE_TAG_DIRTY`
- 数据完整性同步迭代 TOWRITE，使同步开始后变脏的页面不被包含

## Cgroup 写回域抽象

接收 `dirty_throttle_control *dtc` 的代码必须使用 `dtc_dom(dtc)` 获取域，而非直接使用 `global_wb_domain`。`balance_dirty_pages()` 根据 `pos_ratio` 在全局和 memcg 域之间选择；硬编码全局值会在选择 memcg 域时产生错误的节流。

**应报告为 bug**：在接收 `dtc` 参数的函数/跟踪中访问 `global_wb_domain` 字段，除非代码显式操作全局域。

## Swap 缓存驻留

Folio 在回收期间通过 `add_to_swap()` 进入 swap 缓存，并一直保留到显式移除。`folio_free_swap()` 仅在 `folio_swapcache_freeable(folio)`（swapcache，不在写回中，存储未挂起）AND `!folio_swapped(folio)`（无剩余的 swap 引用）时移除它。

**大 folio swapin 冲突**：mTHP swapin 在子页的 swap 槽位已被竞态中的更小 folio 占用时失败并返回 `-EEXIST`。路径必须回退到更小 order 或重试。

**Swap 条目复用（ABA 问题）**：swap 条目被回收——相同的 `swp_entry_t` 可能被重新分配给不同的 folio。`pte_same()` 在 swap PTE 上只确认条目值，不确认 folio 身份。从 `swap_cache_get_folio()` 锁定 folio 后，验证 `folio_test_swapcache(folio)` 和 `folio->swap.val` 仍然匹配。在获取 PTE 锁后（早期查找返回 NULL 时），检查 `si->swap_map[swp_offset(entry)]` 中的 `SWAP_HAS_CACHE`。

## Swap 设备生命周期

在没有引用的情况下访问 `swap_info_struct` 允许 `swapoff` 同时释放它，导致 use-after-free。`swapoff()` 调用 `percpu_ref_kill()` 在 `si->users` 上，后跟 `synchronize_rcu()`，然后才释放结构。

- `get_swap_device(entry)` 验证条目并在 `si->users` 上取 `percpu_ref`。如果设备正在被 swapoff，返回 NULL。必须与 `put_swap_device(si)` 配对
- `__swap_entry_to_info(entry)` 返回 `swap_info_struct` 指针而不取引用——仅当调用者已持有引用或处于 RCU 读端临界区内时安全
- `__read_swap_cache_async()` 内部使用 `__swap_entry_to_info()` 而不固定设备。所有调用者必须持有要读取的条目的设备引用
- **跨设备预读风险**：遍历页表项的预读代码可能遇到与目标不同设备的 swap 条目。来自不同设备的每个条目必须单独用 `get_swap_device()` 固定，或在失败时跳过

## 双回收路径：经典 LRU vs MGLRU

`mm/vmscan.c` 有两个并行的回收实现，必须维护相同的 vmstat、memcg 事件和 tracepoint 覆盖。MGLRU 是运行时可选的，因此 bug 仅在其他路径激活时显现。

- 经典：`shrink_inactive_list()` / `shrink_active_list()`
- MGLRU：`evict_folios()` / `scan_folios()`

两者都调用 `shrink_folio_list()`，但各有自己的回收后统计更新。修改一个函数中的 vmstat 计数器、memcg 事件或 tracepoint 时，验证另一个函数中的对应更改。配对为 `shrink_inactive_list()` ↔ `evict_folios()` 和 `shrink_active_list()` ↔ `scan_folios()`。

## MGLRU Generation 与 Tier 位一致性

当 folio 移动到新的 generation 时，其 tier 位（`LRU_REFS_FLAGS`，即 `LRU_REFS_MASK | BIT(PG_referenced)`）必须被清除，以便 tier 跟踪从零开始。过期 tier 位会抬高访问计数并扭曲驱逐。所有更新 `LRU_GEN_MASK` 的路径也必须清除 `LRU_REFS_FLAGS`。这在 `folio_update_gen()` 和 `folio_inc_gen()` 中完成。`lru_gen_add_folio()` 设置 generation 但不清除 `LRU_REFS_FLAGS`。

**审查任何修改 `folio->flags` 中 `LRU_GEN_MASK` 的代码**，验证它同时处理了 `LRU_REFS_FLAGS`。

## Shmem Folio 缓存驻留

混淆 `folio_test_swapbacked()` 与 `folio_test_swapcache()` 会导致 xarray 损坏、错误的 VM 统计记账以及在迁移和回收路径中的错误分支，因为 shmem folio 可以处于两种不同的缓存状态。

**Shmem 的三种 folio 缓存状态：**

| 状态 | `swapbacked` | `swapcache` | `folio->mapping` | xarray 位置 |
|------|-------------|-------------|-------------------|-------------|
| Shmem 在页缓存中 | true | false | shmem inode `address_space` | `mapping->i_pages`（单个多阶条目） |
| Shmem 在 swap 缓存中 | true | true | NULL | swap 地址空间（N 个独立条目） |
| 匿名在 swap 缓存中 | true | true | `anon_vma`（带 `FOLIO_MAPPING_ANON` 标志） | swap 地址空间（N 个独立条目） |

Shmem folio 要么在页缓存中，要么在 swap 缓存中，永不同时在两者中。一旦移到 swap 缓存，`folio->mapping` 被设置为 NULL，folo 不再与 shmem inode 映射关联。

**`folio_test_swapbacked()` vs `folio_test_swapcache()`：**
- `folio_test_swapbacked()` 测试 `PG_swapbacked`：对所有匿名和 shmem folio 为 true。表示 folio **可以使用** swap 作为后端存储
- `folio_test_swapcache()` 同时测试 `PG_swapbacked` AND `PG_swapcache`：仅当 folio **当前在** swap 缓存中时为 true
- 用 `folio_test_swapbacked()` 作为"在 swap 缓存中"的代理是错误的，因为它也匹配在页缓存中的 shmem folio

**Xarray 存储模型：**
- **页缓存**（`mapping->i_pages`）：为大 folio 存储单个多阶 xarray 条目。操作使用 `xas_store()` 一次
- **Swap 缓存**：存储 N 个独立条目，folo 的每个子页一个。操作必须遍历所有 N 个槽位

在缓存类型之间分支以选择单条目还是多条目 xarray 操作的代码，必须使用 `folio_test_swapcache()`，而非 `folio_test_swapbacked()`。

## Memcg 计费生命周期

每个 `mem_cgroup_charge()` 必须在释放路径上有对应的 `mem_cgroup_uncharge()`。迁移时，计费通过 `mem_cgroup_migrate()` 转移——旧 folio 不会单独取消计费。`folio_unqueue_deferred_split()` 必须在取消计费之前，以避免访问已释放的 memcg 数据。

**Memcg 查找安全：**
- `folio_memcg()` 对未计费的 folio 返回 NULL；可能返回离线的 memcg（folio 保留 `memcg_data` 直到被 reparent）
- 计费/记录/取消计费的操作必须一致地使用已解析的在线祖先
- `mem_cgroup_from_id()` 返回仅在 `rcu_read_lock()` 下有效的 RCU 保护指针。使用 `mem_cgroup_tryget()` 在 `rcu_read_unlock()` 前延长生命周期

**Per-CPU stock drain**：计费在 per-CPU stock 中批处理。销毁 memcg 需要 `drain_all_stock()`——缺失会阻止 cgroup 删除。

## Folio 迁移与睡眠约束

`folio_mc_copy()` 在页面之间调用 `cond_resched()`——对 order-0 安全，但对大 folio 会睡眠。这使得 `filemap_migrate_folio()` / `migrate_folio()` / `__migrate_folio()` 对大 folio 变成睡眠操作。

**应报告为 bug**：在持有 spinlock 时调用这些函数的 `migrate_folio` 回调。改用非阻塞状态标志。

## Folio 隔离用于迁移

并非每个符合迁移条件的 folio 都会被添加到隔离列表：设备一致性 folio 跳过、`folio_isolate_lru()` 可能失败等。`collect_longterm_unpinnable_folios()` 返回所有不可固定 folio 的计数，而非仅已列出的。

**应报告为 bug**：将 `list_empty()` 作为"没有符合条件的项"的代理，而收集有提前 continue 的路径。改用显式计数。

## 快速检查清单

- **LRU 锁下的有界迭代**：跳过 LRU 条目而不推进终止计数器会创建无界的 spinlock 持有扫描。跳过路径必须要么推进计数器，要么有独立的上界
- **迁移锁范围覆盖 unmap 和 remap 阶段**：如果 `TTU_RMAP_LOCKED` 传给 `try_to_migrate()`，`i_mmap_rwsem` 必须保持到 `remove_migration_ptes()` 带 `RMP_LOCKED`。在阶段之间释放会制造 ABBA 死锁
- **kswapd order 下降和水位检查**：`kswapd_shrink_node()` 在回收 `compact_gap(order)` 页后将 `sc->order` 降到 0。使用更严格的高阶度量的水位检查必须检查 `order != 0`，而非静态模式标志。忽略动态 order 下降会导致大量过度回收
- **`folio_putback_lru()` 需要有效的 memcg**：`mem_cgroup_migrate()` 清除源 folio 的 `memcg_data` 后，`folio_putback_lru()` 会触发 memcg 断言。对源 folio 使用纯 `folio_put()`
- **Swap 分配器本地锁范围**：`folio_alloc_swap()` 在 `local_lock()` 下运行。从此范围不可有睡眠操作。释放锁以进行睡眠操作。在典型测试中静默；在 `CONFIG_DEBUG_PREEMPT` 或 PREEMPT_RT 下触发
- **vmscan 中 zone 跳过标准的一致性**：zone 跳过逻辑必须在 `balance_pgdat()`、`pgdat_balanced()`、`allow_direct_reclaim()` 和 `skip_throttle_noprogress()` 中一致。如果一个 zone 跳过一个区而另一个将其计入，`kswapd_failures` 逃逸阀门可能永远不触发
- **计数器门控的跟踪列表移除**：列表成员资格由资源计数器门控。错误路径必须在 `list_del_init()` 前检查计数器——对象可能已从先前操作在列表中。无条件移除会使迭代器永远循环
- **带锁释放的列表迭代**：锁在迭代中间释放时，`list_for_each_entry_safe` 不安全。并发的 `list_del_init()` 会使元素自引用→无限循环。重新获取后，检查 `list_empty()` 并从头开始
