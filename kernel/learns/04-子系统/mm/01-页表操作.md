# MM 页表操作

## 不变式：PTE 状态一致性（PTE State Consistency）

不正确的 PTE（Page Table Entry，页表项）标志组合会导致数据损坏（脏数据被静默丢弃）、安全漏洞（应为只读的页面被错误赋予写权限），以及在捕获非法组合的架构上导致内核崩溃。

**软件强制的不变式（非硬件强制）：**

- **可写的 PTE 必须同时是脏的（dirty）**：一个 clean+writable 的 PTE 是非法的
  - 对于共享映射，`can_change_shared_pte_writable()`（`mm/mprotect.c`）只在 `pte_dirty(pte)` 返回 true 时才返回 true（clean 的共享 PTE 需要通过写时错误（write-fault）触发文件系统的 writenotify）
  - 对于私有/匿名映射，代码路径使用 `pte_mkwrite(pte_mkdirty(entry))` 同时设置两个位（参见 `do_anonymous_page()` 在 `mm/memory.c`，`migrate_vma_insert_page()` 在 `mm/migrate_device.c`）
  - **例外 -- MADV_FREE**：`madvise_free_pte_range()`（`mm/madvise.c`）通过 `clear_young_dirty_ptes()` 清除脏位，但保留写权限，故意创建一个 clean+writable 的 PTE。这使得页面可以在无需写回（writeback）的情况下被回收（页面是 clean 且 lazyfree 的），但如果进程在回收前写入新数据，页面会再次变脏。在 x86 上，`pte_mkclean()` 只清除 `_PAGE_DIRTY_BITS` 而不动 `_PAGE_RW`，硬件直接设置脏位而不触发缺页。在 arm64 上，`pte_mkclean()` 设置 `PTE_RDONLY` 但保留 `PTE_WRITE`；使用 FEAT_HAFDBS 时硬件清除 `PTE_RDONLY`（无缺页），未使用时会触发一个轻量的 minor fault
- **脏（dirty）隐含已访问（accessed）** 是软件约定：`pte_mkdirty()` 并 **不** 设置 accessed 位（x86、arm64 均如此），代码路径必须显式设置两者
- **非已访问 + 可写（non-accessed+writable）** 在没有硬件 A/D 位管理的架构上是无效的（x86 上硬件会在首次访问时自动设置 accessed 位）

### 迁移条目（Migration Entries）

定义在 `include/linux/swapops.h`：
- 通过 `SWP_MIG_YOUNG_BIT` 和 `SWP_MIG_DIRTY_BIT` 编码 A/D 位
- 仅在 `migration_entry_supports_ad()` 返回 true 时可用（取决于架构的 swap offset 是否有足够的空闲位，由 `swap_migration_ad_supported` 在 `mm/swapfile.c` 中控制）
- `make_migration_entry_young()` / `make_migration_entry_dirty()` 将原始 PTE 状态保存到迁移条目中
- `remove_migration_pte()`（`mm/migrate.c`）恢复 A/D 位：仅当迁移条目 **和** folio 都脏时才设置脏位（避免重新脏化迁移过程中已被清理的 folio）

### NUMA 平衡（NUMA Balancing）

参见 `change_pte_range()`（`mm/mprotect.c`）：
- 跳过已经是 `pte_protnone()` 的 PTE，避免双重缺页
- 在应用 NUMA hint fault 前检查 `folio_can_map_prot_numa()`

### Swap 条目

参见 `try_to_unmap_one()`（`mm/rmap.c`）：
- 只有 exclusive、soft-dirty 和 uffd-wp 标志会在 swap PTE 中保留；所有其他 PTE 状态在换出（swap-out）时丢失
- `pte_swp_clear_flags()`（`include/linux/swapops.h`）剥离这些标志以提取裸 swap 条目用于比较

### 非 Present PTE 类型分发（Non-Present PTE Type Dispatch）

非 present 的 PTE 通过 `softleaf_type` / `swp_type` 字段编码多种不同的 swap 条目类型。每种类型都有不同的语义，必须在分发逻辑的正确分支中处理。接受错误的条目类型会导致语义混淆，即使不同类型共享 PFN 编码属性。

不同的非 present PTE 类别包括：

| 类别 | 检查函数 | 说明 |
|------|---------|------|
| 迁移（Migration）`SOFTLEAF_MIGRATION_*` | `softleaf_is_migration()` | 页面在 folio 迁移期间被临时取消映射 |
| 设备私有（Device-private）`SOFTLEAF_DEVICE_PRIVATE_*` | `softleaf_is_device_private()` | 页面被迁移到不可寻址的设备内存（HMM） |
| 设备独占（Device-exclusive）`SOFTLEAF_DEVICE_EXCLUSIVE` | `softleaf_is_device_exclusive()` | CPU 访问被临时撤销用于设备原子操作，页面仍在主机内存中 |
| 硬件错误（HW poison）`SOFTLEAF_HWPOISON` | `softleaf_is_hwpoison()` / `is_hwpoison_entry()` | 页面有不可纠正的内存错误 |
| 标记（Marker）`SOFTLEAF_MARKER` | `softleaf_is_marker()` | 纯元数据条目（如 uffd-wp marker、poison marker） |

**审查要点**：当添加新的 swap 条目类型或修改非 present PTE 的分发逻辑时，验证每个分支只接受语义匹配的条目类型。常见错误是将 device-exclusive 与 migration 归为一类（两者都涉及临时取消映射且都包含 PFN），但它们的 refcount 行为、解析路径和语义完全不同。

### 标志转移：非 Present 到 Present PTE 重建

每个将非 present PTE（swap/migration/device-exclusive 条目）转换为 present PTE 的代码路径，都必须携带 soft-dirty 和 uffd-wp 位。这些位在 swap PTE 和 present PTE 中的编码方式不同，因此需要显式的读-然后-写转移：

```c
if (pte_swp_soft_dirty(old_pte))
    newpte = pte_mksoft_dirty(newpte);
if (pte_swp_uffd_wp(old_pte))
    newpte = pte_mkuffd_wp(newpte);
```

此模式在 `do_swap_page()`、`restore_exclusive_pte()`（`mm/memory.c`）、`remove_migration_pte()`、`try_to_map_unused_to_zeropage()`（`mm/migrate.c`）以及 `unuse_pte()`（`mm/swapfile.c`）中都需要。

### Soft Dirty vs 硬件 Dirty（PTE 移动/重映射）

Soft dirty（`pte_mksoft_dirty()` / `pte_swp_mksoft_dirty()`）是一个用户空间可见的跟踪位，用于 `/proc/pid/pagemap` 和 CRIU，与硬件 dirty（`pte_mkdirty()`）不同。PTE 移动操作（mremap、userfaultfd UFFDIO_MOVE）必须在目标位置设置 soft dirty 以标志映射已变更，同时保留源 PTE 的硬件 dirty 状态。

常见错误：
- 用 `pte_mkdirty()` 代替 `pte_mksoft_dirty()` 来标记"被触摸过"
- 处理 present PTE 时忘记对 swap PTE 使用 `pte_swp_mksoft_dirty()`
- 使用 `#ifdef CONFIG_MEM_SOFT_DIRTY` 而非 `pgtable_supports_soft_dirty()`（后者还能处理运行时检测，如 RISC-V ISA 扩展）

参考实现：`move_soft_dirty_pte()`（`mm/mremap.c`）同时处理 present 和 swap 情况。

## 特殊 vs 普通页表映射

将正常的引用计数 folio 的 PTE 标记为 "special" 会导致 `vm_normal_page()`（以及 `vm_normal_page_pmd()` / `vm_normal_page_pud()`）返回 NULL，从而隐藏 folio 不被页表遍历者（page table walker）、GUP（get_user_pages）和 refcount 管理发现。GUP-fast 会先检查 `pte_special()` / `pmd_special()` / `pud_special()` 并提前退出，回退到 slow GUP。

**不变式**：
- 正常的引用计数 folio 的 PTE 不得标记为 special（`pte_mkspecial()` / `pmd_mkspecial()` / `pud_mkspecial()`）
- 只有原始 PFN 映射（`VM_PFNMAP`、`VM_MIXEDMAP` 中不包含 struct page 的条目）、devmap 条目（`pte_mkdevmap()` / `pmd_mkdevmap()` / `pud_mkdevmap()`）和共享零页（shared zero folios）可以标记为 special
- 为正常引用计数 folio 构造条目时使用 `folio_mk_pmd()` / `folio_mk_pud()`；这些辅助函数产生一个不带 special 位的普通大页条目
- 只有原始 PFN 映射才使用 `pfn_pmd()` + `pmd_mkspecial()` 或 `pfn_pud()` + `pud_mkspecial()`

**常见错误**：当 `vmf_insert_folio_*()` 函数复用了面向 PFN 的辅助函数（如 `vmf_insert_pfn_pud()`）时，该辅助函数无条件调用的 `pXd_mkspecial()` 也会应用到 folio 映射上。修复方法是拆分条目构建逻辑，使 folio 路径使用 `folio_mk_pXd()`（不带 special 位），而 PFN 路径保留 `pXd_mkspecial()`。

## 页表条目到 Folio/Page 转换的前提条件

将 present 条目转换函数应用于非 present 的页表条目（迁移条目、swap 条目、poisoned 条目），会将 swap 元数据位解释为物理页框号（PFN），产生一个错误的 `struct page *`，导致无效地址解引用。

**需要 present 条目的函数：**
- `pmd_folio(pmd)` / `pmd_page(pmd)` -- 仅当 `pmd_present(pmd)` 或 `pmd_trans_huge(pmd)` 或 `pmd_devmap(pmd)` 时有效
- `pte_page(pte)` / `vm_normal_page()` -- 仅当 `pte_present(pte)` 时有效

**非 present 条目的正确转换：**
- 迁移条目：使用 `softleaf_from_pmd()` 或 `softleaf_from_pte()` 提取 `softleaf_t`，然后使用 `softleaf_to_folio()` 获取 folio
- 或者，如果不需要对非 present 条目进行 folio 比较，则完全跳过转换

**审查模式**：当代码处理多种 PMD/PTE 状态的组合条件时，验证后续的 `pmd_folio()` 或 `pmd_page()` 操作只在 present 条目情况下执行。常见错误是在现有条件中添加非 present 条目类型但未调整后面的 folio 提取操作。

## PTE 批处理（PTE Batching）

将映射同一个大 folio 的连续 PTE 合并为一次 `set_ptes()` 调用，会将第一个 PTE 的权限位传播到批次中的所有条目。如果批次中包含不同权限的 PTE（例如可写 vs 只读），结果会静默覆盖预期的权限，导致安全绕过。

`folio_pte_batch()`（`mm/util.c`）是调用 `folio_pte_batch_flags()`（`mm/internal.h`）且 `flags=0` 的简化封装。无标志时，writable、dirty 和 soft-dirty 位的差异被忽略，不同权限的 PTE 会被合并到一起。

**FPB 标志**（`fpb_t`，定义于 `mm/internal.h`）控制批处理时比较哪些 PTE 位：

| 标志 | 效果 |
|------|------|
| `FPB_RESPECT_WRITE` | 在比较中包含 writable 位；写权限不同的 PTE 不会合并 |
| `FPB_RESPECT_DIRTY` | 在比较中包含 dirty 位 |
| `FPB_RESPECT_SOFT_DIRTY` | 在比较中包含 soft-dirty 位 |
| `FPB_MERGE_WRITE` | 合并后，如果任一 PTE 是可写的，则在输出 PTE 上设置 writable 位 |
| `FPB_MERGE_YOUNG_DIRTY` | 合并后，将所有 PTE 的 young 和 dirty 位合并到输出中 |

- `folio_pte_batch()`（无标志）：仅在调用者不将第一个 PTE 的权限位印刻到其他条目上时安全
- `folio_pte_batch_flags()` 加 `FPB_RESPECT_WRITE`：当调用者使用 `set_ptes()` 回写批处理后的 PTE 值时需要

**应报告为 bug**：使用 `folio_pte_batch()`（无标志）确定批次数量然后传给 `set_ptes()` 的代码，因为第一个 PTE 的 writable/dirty/soft-dirty 位会被印刻到所有条目上。

**批处理边界：**
向 `folio_pte_batch()` 传递未封顶的 `max_nr` 会导致越界读取。`max_nr` 必须被限制在一个页表和单个 VMA 范围内。标准的表达式是 `(pmd_addr_end(addr, vma->vm_end) - addr) >> PAGE_SHIFT`。

**应报告为 bug**：任何从 `folio_nr_pages()` 派生 `max_nr` 而不在 PMD 边界处封顶的调用者。

## page_vma_mapped_walk() 与非 Present 条目

对 `page_vma_mapped_walk()` 返回的非 present 条目调用 PTE 访问器函数会产生未定义结果，因为 swap 条目对位的编码方式与 present PTE 不同。

`page_vma_mapped_walk()`（`mm/page_vma_mapped.c`）在 `PVMW_MIGRATION` 未设置时可以返回三种 PTE 类型：

| 条目类型 | `pte_present()` | 如何识别 |
|----------|----------------|----------|
| 普通 present PTE | true | `pte_present(ptep_get(pvmw.pte))` |
| 设备独占 swap 条目（Device-exclusive） | false | `softleaf_is_device_exclusive(...)` |
| 设备私有 swap 条目（Device-private） | false | `softleaf_is_device_private(...)` |

**rmap 遍历回调的规则：**
- 当 `pvmw.pte` 已设置时，始终先检查 `pte_present(ptep_get(pvmw.pte))` 再调用 present-PTE 访问器
- 非 present PFN swap PTE 需要先通过 `softleaf_from_pte()` 转换为 `softleaf_t`，然后使用 `softleaf_to_pfn()` 获取 PFN、使用 `softleaf_is_device_private_write()` 判断可写性。Swap-PTE 标志访问器（`pte_swp_soft_dirty()`、`pte_swp_uffd_wp()`）仍然接受 `pte_t`，但读取的位位置与 present-PTE 对应函数不同，混用会静默读取错误的位
- 非 present PFN swap PTE 从 CPU 视角看是 "old" 和 "clean" 的；MMU notifier 负责设备端的访问跟踪

## 大页 Folio PTE 安装

当 `pte_range_none()` 返回 false（某些 PTE 已被填充）时，处理程序必须确保向前推进：
- **页缓存 folio**（`finish_fault()`）：回退到单 PTE 安装
- **新分配的匿名 folio**（`do_anonymous_page()`）：释放 folio，通过 `alloc_anon_folio()` 以更小尺寸重试
- **PMD 级别**（`do_set_pmd()`）：返回 `VM_FAULT_FALLBACK`

**应报告为 bug**：在 `pte_range_none()` 失败时返回 `VM_FAULT_NOPAGE`（重试）而不回退到单 PTE 的页缓存 folio 处理——这会导致活锁（livelock），进程挂起且无警告。

## 页表遍历器回调（Page Table Walker Callbacks）

`pmd_entry`（`struct mm_walk_ops`，定义于 `include/linux/pagewalk.h`）接收每个非空 PMD，包括 `pmd_trans_huge()`。未能处理 THP PMD 会导致静默的数据跳过或将大页 PFN 当作页表指针使用而导致崩溃。当定义了 `pmd_entry` 但没有 `pte_entry` 时，遍历器不会下探到 PTE——回调必须内部处理 PTE 遍历。

返回值：`0` = 继续，`> 0` = 停止（返回给调用者），`< 0` = 错误。

`walk_lock` 指定锁定方式：`PGWALK_RDLOCK`（mmap_lock 读锁）、`PGWALK_WRLOCK`（遍历器对 VMA 加写锁）、`PGWALK_WRLOCK_VERIFY` / `PGWALK_VMA_RDLOCK_VERIFY`（断言已锁定）。

在 `pmd_entry` 回调中：使用 `pmdp_get_lockless()` 无锁读取 PMD，在 `pmd_lock()` 下为重读 THP；检查 `pte_offset_map_lock()` 的返回值是否为 NULL；若返回 folio 引用，在释放 PTL 前调用 `folio_get()`。

## 快速检查清单

- **TLB 刷写**：使 PTE 权限降低后缺少 TLB 刷写会让用户空间保留过时的写访问权限，导致数据损坏或安全绕过。从可写到只读、从 present 到 not-present 的转换需要 TLB 刷写。not-present 到 present 或变宽松的转换不需要（调用者用 `ptep_set_access_flags()` + `update_mmu_cache()` 配对即可）
- **VM_WRITE 门控**：可写 PTE 需要 `vma->vm_flags` 中有 `VM_WRITE`。使用 `maybe_mkwrite()`。在 fork/COW、userfaultfd 安装和所有 PTE 构造路径中验证——VMA 权限可能在映射和安装之间通过 `mprotect()` 改变
- **VMA 标志与 PTE/PMD 标志一致性**：清除 `vm_flags` 位（如 `VM_UFFD_WP`、`VM_SOFT_DIRTY`）需要清除所有形式（present、swap、PTE marker）的对应 PTE/PMD 位
- **`flush_tlb_batched_pending()`**：在释放并重新获取 PTL 后调用——另一个 CPU 可能已在锁释放期间批处理了 TLB 刷写
- **页表移除 vs GUP-fast**：清除 PUD/PMD 以释放页表页需要 `tlb_remove_table_sync_one()` 或 `tlb_remove_table()`，否则 GUP-fast 在无锁遍历中可能跟随过期条目进入已释放的页表页
- **`vma_start_write()` 必须在访问页表前调用**：`mmap_write_lock` 不排除 per-VMA 锁的读者。调用 `vma_start_write(vma)` 以排干（drain）per-VMA 锁持有者。**关键：PTE 级别的 zap 操作会跨越粒度边界。** VMA 锁定的 `MADV_DONTNEED` 可以通过 `try_to_free_pte()` → `pmd_clear()` 清除 PMD 条目。在 `vma_start_write()` 之前读取 PMD 的代码会持有指向已释放内存的过期指针——这是 use-after-free（内核崩溃），不仅仅是过期数据
- **缺页路径锁约束**：`->fault`/`->page_mkwrite` 在 `mmap_lock` 下运行，嵌套在 `i_rwsem` 和 `sb_start_write` 之下。缺页处理程序不能等待冻结保护（ABBA 死锁）。使用 `copy_folio_from_iter_atomic()` 复制用户数据，在锁外重试
- **`pte_unmap_unlock` 指针必须在 kmap'd PTE 页范围内**：在 `CONFIG_HIGHPTE` 系统上，如果指针跨越页边界，会解除错误页面的映射。保存 `pte_offset_map_lock()` 的起始指针
- **`pte_unmap()` LIFO 顺序**：多个 PTE 映射必须按相反顺序解除映射。在 64 位上不可见；在 32 位 HIGHPTE 上触发 WARNING
- **`pmd_present()` 在 `pmd_trans_huge_lock()` 之后**：对 present THP PMD 和非 present PMD 叶子条目都成功。必须在使用 `pmd_folio()`/`pmd_page()` 之前检查 `pmd_present()`
- **锁释放和重试后的页表状态**：释放并重新获取 PTL 后，并发线程可能已重新填充空条目。释放页表结构的决定必须重新验证
- **内核页表填充同步**：`pgd_populate()` / `p4d_populate()` 不同步到其他进程的内核页表。使用 `pgd_populate_kernel()` / `p4d_populate_kernel()`（调用 `arch_sync_kernel_mappings()`）。影响 vmemmap、percpu、KASAN shadow
- **惰性 MMU 模式配对与风险**：(1) 在惰性模式中对 PTE 写入后读取可能返回过期数据——用 leave/enter 配对。(2) 错误路径不能跳过 `arch_leave_lazy_mmu_mode()`——使用 `break` 而非 `return`。无操作对大多数配置；bug 仅出现在 Xen PV、sparc、powerpc book3s64、arm64 上
- **惰性 MMU 模式可能意味着原子上下文**：在某些架构上禁用抢占。`pte_fn_t` 回调和 PTE 循环在惰性 MMU 模式下不能睡眠。分配需要 `GFP_ATOMIC`/`GFP_NOWAIT` 或预分配
- **`arch_sync_kernel_mappings()` 在错误路径上**：累积了 `pgtbl_mod_mask` 并调用 `arch_sync_kernel_mappings()` 的循环必须在错误时使用 `break`（非 `return`）。提前 `return` 跳过同步，使其他进程的内核页表过期
- **页表遍历器迭代器推进**：在 `do { } while` 页表循环中，在 `while` 子句中无条件推进指针。不在条件体内放置 `ptr++`
- **非 present PTE 条目的 mapcount 对称性**：持有 folio 引用的非 present swap PTE（device-private、device-exclusive、migration）必须保持 mapcount 对称：如果在创建时维护了 mapcount，则在销毁时必须移除它
- **PTE 批次循环边界**：不能仅依赖 `pte_same()` 来约束迭代。在 XEN PV 上，`pte_advance_pfn()` 可能为没有有效 machine frame 的 PFN 产生 `pte_none()`，导致假匹配并超出 folio 范围。必须使用 folio 元数据独立约束迭代
- **`pte_offset_map`/`pte_unmap` 配对**：`pte_unmap()` 必须接收 `pte_offset_map()` 的精确指针，不能指向本地 `pte_t` 拷贝。常见错误：`pte_t orig = ptep_get(pte)` 然后 `pte_unmap(&orig)`
- **内存热插拔锁用于无保护的内核页表遍历**：在任意或热插拔可移除的 direct-map/vmemmap 范围内遍历 `init_mm` 内核页表，除了 `mmap_lock` 外还需要 `get_online_mems()` / `put_online_mems()` 排他。在 `mmap_lock` 前获取热插拔读锁以保持锁顺序
- **基于位的锁屏障配对**：当位标志用于互斥时，解锁必须使用 `clear_bit_unlock()`（release 语义），而非 `clear_bit()`（宽松，无屏障）。加锁方必须使用 `test_and_set_bit_lock()`（acquire 语义）。MM 在 `mm/vmscan.c` 中对 `PGDAT_RECLAIM_LOCKED` 使用此模式
- **`walk_page_range()` 默认跳过 `VM_PFNMAP` VMA**：没有 `.test_walk` 时，默认的 `walk_page_test()` 静默跳过 `VM_PFNMAP`。需要所有 VMA 的调用者必须提供返回 0 的 `.test_walk`。`walk_page_range()` 返回 0 可能意味着 "已跳过"，而不是 "已处理"
- **`ACTION_AGAIN` 在页表遍历回调中**：`ACTION_AGAIN` 无限重试。`pte_offset_map_lock()` 返回 NULL 可能是非瞬时的——在此失败上设置 `ACTION_AGAIN` 会创建无限循环。返回 0 优雅跳过
- **零页重映射的页面比较必须使用 `pages_identical()`**：原始的 `memchr_inv()`/`memcmp()` 会遗漏架构元数据。在 arm64 MTE 上，字节相同但标签不同的页面在重映射到 `ZERO_PAGE(0)` 后会导致不匹配错误。**应报告为 bug**：对 zeropage/merge 决定使用 `memchr_inv()`/`memcmp()`
