# 内核构建系统要点

## 概述

Linux 内核构建系统（Kbuild）有其独特的工具链要求和语言标准配置。理解这些约束有助于避免在代码审查或开发中产生误判。

---

## Python 兼容性

内核构建系统和辅助脚本**要求 Python 3**。

- 所有 `.py` 文件（位于 `scripts/`、`tools/`、`Documentation/`）都应使用 Python 3 语法。
- Python 2 特性（如 `print` 语句、旧式字符串格式化）不是兼容性要求。
- Python 3 特性——类型注解（type annotations）、`print()` 函数、f-strings——都是合法用法，不应标记为问题。

记住：强制 Python 2 兼容性会产生**误报**（false positives）。

---

## 工具链要求

内核有明确的最低工具版本要求，记录在 `Documentation/process/changes.rst` 中：

- **编译器**：GCC、Clang 均有最低版本要求
- **构建工具**：Make、flex、bison 等
- **架构限制**：某些架构可能有额外的工具链要求

不应假设需要旧版本工具，除非架构约束明确要求。在报告工具链问题时，务必对照官方文档核实。

---

## C 标准与编译标志

内核 C 代码使用与用户空间不同的编译配置。

### 语言标准

- 内核使用 **GNU C11**（`gnu11`），详见 `Documentation/process/programming-language.rst`。
- GNU 扩展——语句表达式（statement expressions）、`typeof`、零长度数组（zero-length arrays）、case 范围（case ranges）——都是合法用法，不应标记为非标准。

### unsigned char

- 顶层 `Makefile` 通过 `-funsigned-char` 在所有架构上强制 `char` 为无符号类型。
- 因此在内核代码中检查 `char < 0` 要么是死代码（dead code），要么是逻辑错误。

### 严格别名

| 代码区域 | 别名规则 | 说明 |
|---|---|---|
| 内核核心代码 | `-fno-strict-aliasing`（关闭） | 类型双关（type punning）和指针转换不是未定义行为 |
| `tools/` 目录下 | `-fstrict-aliasing`（标准） | 类型双关和不兼容指针转换是警告对象 |

内核核心代码关闭了严格别名，因此不要报告类型双关或指针转换为未定义行为。但 `tools/` 下的代码使用标准严格别名规则，类型双关在那里需要警惕。

---

## 快速检查清单

| 检查项 | 要点 |
|---|---|
| Python 3 | 不对内核脚本强制 Python 2 兼容 |
| 工具版本 | 对照 `Documentation/process/changes.rst` 核实 |
| C 标准 | 使用 `gnu11`，GNU 扩展合法 |
| char 类型 | `-funsigned-char` 生效，检查 `char < 0` 是错误 |
| 别名规则 | 内核代码 `-fno-strict-aliasing`，`tools/` 下为标准别名 |
