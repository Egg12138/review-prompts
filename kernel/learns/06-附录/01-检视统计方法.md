# 检视统计方法

## 用途

本方法用于衡量 AI 补丁审查的有效性。通过分析审查线索中的 AI 审查及其回复，统计审查的正确性。

## 统计任务

给定一个邮件消息 ID，使用工具找到该消息的完整线索：

1. 从带回复的 lore 查询开始
2. 必要时扩展到完整线索

## 两个任务

本方法包含两个必须完成的任务。

### 任务 1：读取完整线索

1. **显示线索中的邮件数量**
2. **显示 AI 审查的消息 ID**

如果验证失败，必须重新开始。

### 任务 2：检查后续版本

检查后续邮件中是否有相同主题的更新补丁，查看审查意见是否被处理。

**显示更新补丁系列消息的数量。**

如果验证失败，必须重新开始。

## 统计分类

### 审查正确性分类

每条 AI 审查按以下方式分类：

- **正确 (correct)** — 审查指出的 bug 真实存在
- **部分正确 (partially correct)** — 审查指出多个问题，部分正确部分错误
- **不正确 (incorrect)** — 审查指出的问题不存在
- **无回复 (no response)** — 没有回复，无法判断

### Bug 类别分类

| 类别 | 说明 |
|------|------|
| 逻辑错误 | 条件倒置、变量用错、差一错误 |
| 内存问题 | 泄漏、未初始化变量、缓冲区溢出 |
| 类型不匹配 | 符号错误、size_t vs ssize_t |
| 缺失错误处理 | 未检查返回值、缺少清理 |
| 竞态条件 | TOCTOU、缺少锁、同步问题 |
| 配置问题 | 缺少 #ifdef 回退、构建失败 |
| 文档错误 | 不正确的 API 文档、误导性注释 |
| 空指针问题 | 缺少 NULL 检查、潜在解引用 |
| 其他 | 不属于以上任何类别 |

## review-analysis.txt 文件

这是一个纯文本文件，汇总了所有线索的分析结果。每次分析新线索后更新该文件。

**格式要求：**
- 纯文本，无 markdown 格式
- 每行在 78 字符处换行（主题行从不换行）
- 精确匹配模板格式

```
Number of review threads [N]
Number of correct reviews [N]
Number of correct reviews fixed in later versions [N]
Number of partially correct reviews [N]
Number of incorrect reviews [N]

**Bug Categories:**
- **Logic errors** (inverted conditions, wrong variables, off-by-one)
  - Number correct [N]
  - Number incorrect [N]
- **Memory issues** (leaks, uninitialized variables, buffer overflows)
  - Number correct [N]
  - Number incorrect [N]
- **Missing error handling** (unchecked returns, missing cleanup)
  - Number correct [N]
  - Number incorrect [N]
- **Race conditions** (TOCTOU, missing locks, synchronization issues)
  - Number correct [N]
  - Number incorrect [N]
- **Configuration issues** (missing #ifdef fallbacks, build failures)
  - Number correct [N]
  - Number incorrect [N]
- **Documentation errors** (incorrect API docs, misleading comments)
  - Number correct [N]
  - Number incorrect [N]
- **Type mismatches** (sign errors, size_t vs ssize_t)
  - Number correct [N]
  - Number incorrect [N]
- **Null pointer issues** (missing NULL checks, potential dereferences)
  - Number correct [N]
  - Number incorrect [N]
- **Everything else** (doesn't fit into any category)
  - Number correct [N]
  - Number incorrect [N]
```

## review-details.txt 文件

这是第二个文件，包含每个线索的详细信息。每次分析新线索时追加新条目。

**格式要求：**
- 纯文本，无 markdown 格式
- 每行在 78 字符处换行（主题行从不换行）
- 精确匹配模板格式

```
REVIEW <N>

msgid: <msg id of review email>
subject: <subject of email being reviewed>
author: <original author of the patch>
date: <date of the review email>
review category: <where it was counted in review-analysis.md>
review correct: <yes/no/partial/no response>
review email: http://lore.kernel.org/all/<msgid>
Later version with fixes: http://lore.kernel.org/all/<msgid>

<exactly one blank line>

at most 6 lines describing the review and the interactions on the list.
```

### 操作注意事项

- 如果 `review-details.txt` 已存在，先读取现有内容，然后追加新条目
- 永远不要使用 Write 工具覆盖——只使用 Edit 追加，或先 Read 再 Write 包含所有现有内容加新内容
