# 自动化脚本概览

这些脚本自动化了使用 AI 审查一系列 git 提交的过程。

## 脚本总览

| 脚本 | 用途 |
|------|------|
| `create_changes.py` | 提取和分类提交变更，用于结构化审查 |
| `review_one.sh` | 审查单个提交 |
| `claude_xargs.py` | 并行运行多个审查 |
| `claude-json.py` | 将 AI 的 stream-json 输出解析为 markdown |
| `lore-reply` | 创建回复邮件回复 lore.kernel.org 上的补丁 |

---

## create_changes.py

从 Linux 内核提交中提取提交信息并将变更分类为适合并行代理审查的结构化格式。

### 安装

```bash
ln -s /path/to/review-prompts/kernel/scripts/create_changes.py ~/.local/bin/create_changes.py
# 或
cp /path/to/review-prompts/kernel/scripts/create_changes.py ~/.local/bin/
```

### 用法

```bash
create_changes.py [options] <commit_ref>
```

### 选项

| 选项 | 说明 | 默认 |
|------|------|------|
| `<commit_ref>` | 提交引用（SHA、HEAD 等）或补丁文件路径 | `HEAD` |
| `-o, --output-dir` | 输出文件目录 | `./review-context` |
| `-C, --git-dir` | Git 仓库目录 | 当前目录 |
| `--no-semcode` | 跳过代码分析工具集成 | 自动检测 |

### 功能

1. 读取提交（或补丁文件）并提取元数据（SHA、作者、日期、主题、正文、标签）
2. 将 diff 解析为 hunks，按源文件和函数分组
3. 如果存在代码分析数据库则使用静态分析；否则回退到基于 Python 的解析器
4. 智能合并小的变更
5. 将大文件拆分为多个组
6. 为下游审查代理写入结构化输出

### 输出文件

所有输出输出到 `--output-dir` 目录（默认 `./review-context/`）：

| 文件 | 说明 |
|------|------|
| `change.diff` | 完整提交消息和统一 diff |
| `commit-message.json` | 解析后的提交元数据 |
| `index.json` | 所有文件和变更的索引 |
| `FILE-N-CHANGE-M.json` | 每个变更一个文件，按源文件分组 |

## review_one.sh

审查单个 git 提交：创建工作树并运行 AI 审查。

### 用法

```bash
review_one.sh [options] <sha>
```

### 选项

| 选项 | 说明 | 默认 |
|------|------|------|
| `--linux <path>` | 基础 linux 目录路径 | `./linux` |
| `--prompt <file>` | 审查提示文件路径 | `../review-core.md` |
| `--series <sha>` | 系列中最后一个提交的 SHA | - |
| `--working-dir <dir>` | 创建工作树的目录 | 当前目录或 `$WORKING_DIR` |
| `--model <model>` | AI 模型 | `sonnet` 或 `$CLAUDE_MODEL` |

### 功能

1. 为指定提交创建 git 工作树
2. 如果基础 linux 目录有代码分析数据库，硬链接到工作树中
3. 运行 AI 审查
4. 输出结果到 `review.json`、`review.md`、`review.duration.txt`
5. 如果 AI 无输出退出，最多重试 5 次

## claude_xargs.py

类似于 xargs，但带超时支持和正确的信号处理，并行运行多个命令。

### 用法

```bash
claude_xargs.py -c <command> -f <sha_file> [options]
```

### 功能

- 使用线程池并行运行命令
- 支持 Ctrl-C 优雅退出，杀死所有衍生进程
- 支持每命令超时
- 报告进度和失败计数

## claude-json.py

将 AI 的 stream-json 输出格式解析为纯文本/markdown。

### 用法

```bash
claude -p "prompt" --output-format=stream-json | python claude-json.py
python claude-json.py -i input.json -o output.txt
```

### 为什么存在

使用 AI 的非交互模式时，正常输出被禁用。捕获输出的唯一方式是使用 `--output-format=stream-json` 和 `--verbose`。此脚本将该 JSON 流解析回可读的 markdown。

## 完整工作流示例

审查应用于 linux 的补丁系列：

```bash
# 1. 准备 linux 树
cd linux
git reset --hard v6.19
git am -s patches/*.patch
git rev-list v6.19..HEAD > ../series

# 2. 用代码分析工具索引（推荐但非必须）
semcode-index -s . --git v6.19..HEAD

# 3. 运行并行审查
cd ..
/path/to/scripts/claude_xargs.py \
    -n 10 \
    -f series \
    -c "/path/to/scripts/review_one.sh" \
    --series $(git -C linux rev-parse HEAD)
```

### 输出

完成后，会有：
- `linux.<sha>/` 每个提交的目录
- `linux.<sha>/review.md` 每个提交的审查
- `linux.<sha>/review-inline.txt` 发现的 bug（如果有）
- `linux.<sha>/review.duration.txt` 每次审查耗时
